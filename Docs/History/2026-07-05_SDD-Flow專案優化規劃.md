# SDD-Flow 專案優化規劃

## 目的

本文件記錄 2026-07-05 對 SDD-Flow 樣板工作區的快速盤點結果，並於 2026-07-06、2026-07-15 複核目前狀態。目標是把可被其他模型或人工審查交叉驗證的改善點整理成具體、可執行、可驗收的計畫。

> 重要前提：此 repository 是供其他專案初始化使用的樣板，不是單一產品專案。因此 `.specify/memory/constitution.md` 保持 Spec Kit placeholder 屬於合理設計；`Docs/guides/棕地專案初始憲章.md` 是給人類閱讀與複製參考的範本文件，不應直接覆寫 active constitution。

## 盤點範圍

- 專案根目錄文件：`README.md`、`AGENTS.md`
- Spec Kit 設定：`.specify/memory/`、`.specify/templates/`、`.specify/scripts/`

- Agent skills：`.agents/skills/`
- 工作區治理：`.gitignore`、`.copilotignore`、`.vscode/settings.json`、`.github/workflows/`

## 優化原則

1. 尊重樣板定位，不把單一專案憲章寫死到 `.specify/memory/constitution.md`。
2. 優先修正會被下游專案繼承的安全與可見性預設。
3. 對 Spec Kit 上游受管檔案採最小覆寫，避免未來自動更新衝突。
4. 每個改善項都要有可重跑的驗證命令。
5. 優先處理會導致其他 agent 誤判或 guard 失效的設定錯置。

## Spec Kit 定期更新注意事項

- GitHub Actions 目前透過 `uvx --from "git+https://github.com/github/spec-kit.git@${LATEST}" specify init --here --force --integration copilot` 定期建立更新 PR。
- `.specify/integrations/copilot.manifest.json` 目前列出的上游管理檔案主要是 `.github/agents/speckit.*.agent.md` 與 `.github/prompts/speckit.*.prompt.md`。

- 若未來 Spec Kit upstream 開始管理 `.github/hooks/` 或更多 `.github/agents/` 檔案，需重新評估本樣板的自訂檔案是否要搬到獨立目錄或加入更新後檢查。

# Agents 技能強化與優化複核報告

> **建立日期**：2026-08-02  
> **複核日期**：2026-08-02  
> **維護目的**：複核 29 個 Custom Agents 與 24 個專案 Skills 的發現、委派與角色協作機制，並記錄已驗證的最小修正。

---

## 1. 複核結論

依 [VS Code Agent Skills 官方文件](https://code.visualstudio.com/docs/agent-customization/agent-skills#_how-copilot-uses-skills)，Skills 會先以 `SKILL.md` frontmatter 的 `name` 與 `description` 判斷相關性，再按需載入正文與資源。Custom Agent 不需要為了自動發現而重複列出所有相關 Skills。

原建議所述「未顯式引用會導致無法自動載入」不成立。複核後確認真正的阻塞點是 Agent 委派設定：

- [BA Agent](../../.github/agents/ba.agent.md) 明定 Phase 1–5 必須使用 `agent` 工具委派專責角色。
- BA allowlist 中有 17 個專責角色同時設定 `user-invocable: false` 與 `disable-model-invocation: true`，造成它們既不出現在 Agent picker，也無法由 BA 委派。
- `code-reuse-check`、`python-venv-check`、`karpathy-guidelines` 與 `rtk-token-killer` 已由 [AGENTS.md](../../AGENTS.md) 全域強制或預載，不應在各 Agent 重複說明。

依 [consistency-check](../../.agents/skills/consistency-check/SKILL_zhTW.md) 以 `--strict` 模式檢測，結果如下：

- **內容重複掃描檔案數**：30
- **載入指令掃描檔案數**：51
- **檢測結果**：✅ **0 個錯誤或警告**（符合 SSOT 單一真相來源與無重複載入原則）。

---

## 2. 原建議調整結果

| 範圍 | 決策 | 理由 |
|---|---|---|
| 17 個專責角色 | 將 `disable-model-invocation` 改為 `false` | 恢復 BA 委派能力；保留 `user-invocable: false`，不增加 picker 雜訊 |
| `test-review` | 條件式引用 `webapp-testing` 與 `integration-test-quality` | 前者僅用於 Web UI／瀏覽器互動；後者僅適用 ASP.NET MVC integration test suite |
| `critic` | 直接增加重複實作與未授權抽象檢查 | 這是角色審查責任，不需要重載全域 Skills |
| `software-engineer`、`migration-engineer` | 不增加技能清單 | 查重、最小變更、Python 環境與 RTK 已由全域治理涵蓋 |
| `fullstack-engineer` | 不加入 `frontend-design` | 新 UI 已明確路由至 `frontend-designer`，避免角色邊界衝突 |
| `debugger` | 不加入 `webapp-testing` | Debugger 為唯讀角色且沒有 `edit` 工具，無法依該 Skill 建立 Playwright 腳本 |
| `system-architect` | 不加入 `doc-coauthoring` | 該 Skill 是面向使用者的互動式共筆流程，不符合 sub-agent 邊界 |
| `tool-expert` | 不維護靜態技能目錄 | `hush` 僅支援 macOS，其他工具亦有條件式觸發範圍，應由 Skill description 按需發現 |

---

## 3. 已套用變更

1. BA allowlist 中原本被禁止 model invocation 的 17 個專責角色已改為 `disable-model-invocation: false`；BA 本身維持 `true`，保留使用者唯一入口。
2. [test-review.agent.md](../../.github/agents/test-review.agent.md) 已加入兩項條件式 Skill 路由，並明確限制 ASP.NET MVC 專屬門檻不得套用到其他技術棧。
3. [critic.agent.md](../../.github/agents/critic.agent.md) 已將重複既有實作與 Task 未要求的抽象納入可維護性審查，且維持唯讀回報責任。
4. 未在其他 Agent 新增通用「相關技能指引」段落，避免重複上下文與後續維護漂移。

---

## 4. 驗證結果

- **實際委派 smoke test**：`tool-expert`、`software-engineer`、`critic` 均可由 model invocation 成功啟動。
- **角色指令載入**：`software-engineer` 在缺少 `T###` 時依 blocking requirement 停止；`critic` 正確維持唯讀審查；`tool-expert` 正確回報工具診斷職責。
- **治理檢測**：依 `consistency-check` Skill 執行 `--strict`，30 個內容掃描檔與 51 個載入掃描檔皆未發現問題。
- **後續驗證方式**：修改 Agent 或 Skill 後，依 `consistency-check` Skill 執行 strict gate；若變更 invocation frontmatter，再以一個唯讀角色與一個實作角色各做一次最小委派測試。

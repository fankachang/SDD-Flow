## 一、核心原則：最小高訊號 Token 集合

AGENTS.md 應只保留每個工作階段都需要的高價值資訊，避免放入過多背景說明、完整文件或罕見的邊界案例。

## 二、控制檔案長度

研究建議：

- Anthropic 建議 CLAUDE.md 控制在 **200 行以內**。
- Augment Code 的評測顯示，**100–150 行**通常效果最佳。
- 超過適當長度後，內容增加可能導致效益下降。
- 深度細節應移至參考文件、Skills 或路徑範圍規則。

## 三、採用漸進式揭露

AGENTS.md 應扮演入口與索引的角色，只放置必要資訊，其他內容在需要時再載入。

Vercel 的實驗顯示，將約 40KB 的完整文件壓縮成 8KB 的索引後，仍能維持 **100% 的通過率**。

## 四、指令應具體並優先呈現

應避免使用模糊描述，例如「妥善格式化程式碼」，而應改為具體規則，例如：

> 使用 2 格縮排。

建置、測試與常用開發指令也應放在文件前段，讓代理能快速找到並執行。

## 五、範例勝過冗長說明

3–10 行的真實程式碼範例，通常比大段抽象文字更容易讓 AI 代理理解專案風格與實作方式。

## 六、禁止事項應搭配替代方案

不要只寫「不要直接建立 HTTP client」，還應明確說明：

> 改用 `apiClient`。

「禁止事項 + 建議做法」的寫法，比只有負面規則更能避免代理過度保守或反覆探索。

## 七、依工具特性調整內容

Codex、Claude Code、Cursor 和 GitHub Copilot 的載入方式與大小限制不同，因此 AGENTS.md 不宜採用完全相同的格式與長度。

撰寫時應考慮：

- 工具是否完整載入檔案。
- 是否支援巢狀 AGENTS.md。
- 是否支援 Skills 或路徑範圍規則。
- 是否存在內容大小或行數限制。

## 八、善用 Token 節省技巧

研究建議：

- 先搜尋，再讀取大型檔案的指定範圍。
- 避免重複讀取尚未變更的內容。
- 批次完成相關修改後，再執行建置。
- 將建置或測試輸出保存後重複分析。
- 使用子代理處理複雜探索，主代理只接收摘要。
- 維持穩定的前綴內容，以提高 Prefix Caching 命中率。

## 九、AGENTS.md 並非所有專案都必需

如果專案本身已具備：

- 清楚的文件。
- 完善的測試。
- 一致的程式碼結構。
- 明確且可讀的範例。

那麼 AI 代理可能不需要大量額外指令。AGENTS.md 應用來補足專案特有規則，或解決代理反覆犯下的錯誤，而不是取代良好的程式碼與文件。

## 十、注意資料可信度差異

文章將研究內容分為不同信心等級：

- Anthropic、Vercel、Cursor 等官方文件與量化數據，可信度較高。
- 社群評論與單一來源資料，應適度保留。
- 未驗證的專家引述、搜尋結果或本地研究，應審慎解讀。

## 總結

主要結論是：

> **AGENTS.md 的效率不在於內容越多越好，而在於以最少的 Token 提供最重要、最具體且最容易執行的專案指引。**

實務上，建議將 AGENTS.md 控制在約 **100–150 行**，優先包含：

1. 技術棧與版本。
2. 安裝、建置與測試指令。
3. 專案目錄結構。
4. 重要程式碼慣例。
5. 明確的操作邊界。
6. PR 與 Commit 規範。
7. 深度文件與 Skills 的參考路徑。

其他較複雜的流程、背景資料與特定目錄規則，則應移至參考文件、Skills 或路徑範圍規則。文件也應根據 AI 代理實際犯錯的情況持續迭代，而不是一開始就建立冗長且難以維護的規範。
